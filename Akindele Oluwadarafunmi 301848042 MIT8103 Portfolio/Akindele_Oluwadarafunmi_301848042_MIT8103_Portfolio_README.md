 Project overview
This project models a University Student Result Portal for managing departments, students, lecturers, courses, semesters, course offerings, enrolments, and results.

 Repository contents
- `portfolio-1-database-design/`: relational schema, sample data, ER model notes, normalisation notes.
- `portfolio-2-query-optimisation/`: result queries, indexing experiments, synthetic benchmark, execution-plan capture instructions.
- `portfolio-3-transactions-concurrency/`: transaction and two-session concurrency experiments.
- `portfolio-4-nosql/`: MongoDB sample document and implementation commands.
- `portfolio-5-distributed-cloud/`: proposed architecture and design discussion.
- `documentation/`: final-summary template and AI-use declaration.
- `evidence/`: folders for screenshots and actual outputs from your environment.

 How to run
1. Create a separate practice database in PostgreSQL.
2. Run `portfolio-1-database-design/schema.sql`.
3. Run `portfolio-1-database-design/sample-data.sql`.
4. Run and verify the queries in each portfolio folder.
5. Run the MongoDB commands in `portfolio-4-nosql/mongodb-commands.js` in a MongoDB shell.
6. Capture your own screenshots and save actual outputs under `evidence/`.
7. Update the final summary with observed results, your own reflection, student ID, and GitHub URL.

 Important verification note
Execution plans, timings, screenshots, cloud configuration, and replication evidence must come from your own environment. Placeholder files are not evidence of completed tests. Clearly identify the distributed/cloud section as a design exercise unless you actually deploy and test it.
